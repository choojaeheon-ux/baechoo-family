# 예산 「버전」 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 예산을 시작월을 가진 「버전」으로 묶어, 새 기준선을 만들어도 과거 달의 소진률·리포트가 소급 변경되지 않게 한다.

**Architecture:** `budget_versions` 테이블 하나를 추가하고 `budgets.version_id`로 예산 행을 버전에 묶는다. 어떤 달의 예산은 "시작월이 그 달 이하인 버전 중 가장 늦은 것"의 행들이다. 해석은 `lib/compute.ts`의 순수함수 `resolveVersion`/`budgetsOfMonth`가 담당하고, 기존 예산 계산 함수들은 `versions` 인자를 하나 더 받는다. 화면은 가계부에 5번째 서브탭 「예산」을 신설해 버전 목록·복제·금액 편집을 한곳에서 하고, 손익의 예산 섹션은 걷어낸다.

**Tech Stack:** Next.js 16 (App Router) · TypeScript · Tailwind v4 · Supabase (PostgREST) · vitest

**정본 스펙:** `docs/superpowers/specs/2026-08-02-예산-버전-design.md`

## Global Constraints

- **UI 문구·주석은 한국어.** 이모지는 절제한다. 화면에 정의·산식을 설명하는 안내 문구를 넣지 않는다(맥락은 코드 주석으로).
- **신규 npm 의존성 0.**
- 이 저장소의 Next.js는 학습 데이터와 다르다. 코드 작성 전 `node_modules/next/dist/docs/`의 해당 가이드를 읽는다 (`AGENTS.md`).
- **`budgets.id`는 uuid 타입**이다(`categories.id`는 text). 슬러그를 넣으면 PostgREST가 400 `22P02`를 낸다. 새 예산 행 id는 `repo.newId()`(= `crypto.randomUUID()`)를 쓴다.
- **`budget_versions.id`는 text 슬러그** (`bv-1`, `bv-<uuid>`).
- **금융 테이블(`transactions`·`categories`·`budgets`·`recurring_expenses`·`budget_versions`)에는 `deleted_at`이 없다.** `.is("deleted_at", null)` 필터를 걸면 PostgREST가 `42703`으로 400을 낸다. 소프트 삭제를 도입하지 않는다.
- **테스트 픽스처에 실금액을 쓰지 않는다.** 300,000·700,000처럼 둥근 수가 하필 실제 예산과 일치해 세 번 반복된 실수다. 새 테스트는 12,345 / 23,456 계열의 눈에 띄는 값을 쓴다.
- **DDL을 배포보다 먼저 적용한다** (Task 1이 Task 8보다 앞서는 이유). 0024 때 push가 DDL보다 먼저 나가 저장이 조용히 실패하는 창이 열렸다.

```sql
-- 0025: budget_versions — 예산 기준선을 버전으로 묶는다.
-- 각 버전이 start_month를 갖고, 어떤 달의 예산은
-- "start_month <= 그 달" 중 가장 늦은 버전의 행들이다.
-- 이렇게 해야 새 기준선을 만들어도 과거 달이 소급 변경되지 않는다.
--
-- 한글 이름은 여기서 넣지 않는다(0021에서 정한 규칙 — 인코딩 손상 방지).
-- v1 이름은 ASCII로 두고, 사용자가 앱에서 바꾼다.

create table if not exists budget_versions (
  id          text primary key,
  name        text not null,
  start_month text not null,
  memo        text,
  created_at  timestamptz default now()
);

alter table budget_versions enable row level security;
drop policy if exists family_all on budget_versions;
create policy family_all on budget_versions for all using (true) with check (true);
create index if not exists idx_budget_versions_start on budget_versions (start_month);

-- budgets를 버전에 묶는다.
alter table budgets add column if not exists version_id text references budget_versions(id);

-- v1 = 첫 기준. 시작월은 첫 거래월(2026-06).
insert into budget_versions (id, name, start_month)
values ('bv-1', 'v1', '2026-06')
on conflict (id) do nothing;

-- 기존 예산 전체를 v1으로 백필.
update budgets set version_id = 'bv-1' where version_id is null;

-- year_month 컬럼은 남긴다. 「이번 달만 조정」 개념은 폐지했지만
-- 되돌릴 여지를 두기 위해 컬럼과 기존 값을 보존한다.
```

```ts
/* ───────────── 예산 버전 해석 ───────────── */

// 그 달에 적용되는 예산 버전.
// 시작월이 그 달 이하인 버전 중 가장 늦은 것. 하나도 없으면 가장 이른 버전으로
// 폴백한다 — 가장 이른 시작월보다 앞선 달에도 예산이 통째로 사라지지 않게.
export function resolveVersion(
  versions: BudgetVersion[],
  ym: string
): BudgetVersion | null {
  if (versions.length === 0) return null;
  const sorted = [...versions].sort(
    (a, b) =>
      a.startMonth.localeCompare(b.startMonth) ||
      a.createdAt.localeCompare(b.createdAt) ||
      a.id.localeCompare(b.id)
  );
  let found: BudgetVersion | null = null;
  for (const v of sorted) {
    if (v.startMonth <= ym) found = v;
  }
  return found ?? sorted[0];
}

// 그 달에 적용되는 버전의 예산 행만 남긴다.
// 버전에 없는 과목이 다른 버전 행으로 대체되면 안 된다 —
// 계정과목 폐지가 자동으로 풀리는 것이 이 설계의 핵심이다.
export function budgetsOfMonth(
  budgets: Budget[],
  versions: BudgetVersion[],
  ym: string
): Budget[] {
  const v = resolveVersion(versions, ym);
  if (!v) return [];
  return budgets.filter((b) => b.versionId === v.id);
}
```
