# 배추 탭 개편 — 원탭 기록 + 패턴 (베이비타임형)

- 작성: 2026-10-06 · 브랜치 `feat/app-overhaul`(묶음 배포, 미push)
- 요청: 재헌 — "배추 기록이 귀찮은 형태. 베이비타임처럼 동그라미 버튼 한 번으로 기록하고, 나중에 눌러서 상세를 고친다. 기록이 한눈에 보이는 패턴 탭이 필요하다."

## 1. 왜 바꾸나

지금은 기록 하나에 시트를 열고 구분·날짜·시간·사료·토핑·양을 채워야 저장된다. 그 결과 **식사 기록이 10/1 이후 끊겼다**(241건 중 마지막이 10/1). 반면 산책은 오늘까지 매일 쌓였다.

목표는 하나다 — **기록하는 순간의 마찰을 0으로.** 누르면 지금 시각으로 바로 저장되고, 상세는 나중에 타임라인에서 고친다. 그리고 쌓인 기록을 하루 일과 패턴으로 한눈에 본다.

### 실데이터 (2026-10-06, 읽기 전용 집계)

| 기록 | 건수 | 시각 | 비고 |
|---|---|---|---|
| 식사·간식 | 241 (식사 190·간식 51) | 전부 `time` 있음 | 직전 식사와 사료가 같은 비율 68% |
| 산책 | 210 | 전부 `start_time`·`duration_sec` | 최근 30일 49건 중 48건이 GPS 추적, 중앙값 13분 |
| 응가(산책 내) | 131 | `time` 있음 | 130건이 「정상」 |
| 건강 기록 | 18 | **날짜만** | 최근 30일 0건 |

## 3. 데이터

### 3.1 마이그레이션 0028 (가산적·idempotent, 순수 ASCII)

```sql
-- (1) 기타 기록 시각
alter table baechoo_health add column if not exists time text; -- HH:MM, null 허용

-- (2) 산책과 별개인 응가 기록
create table if not exists baechoo_stools (
  id text primary key,
  date date not null,
  time text,                       -- HH:MM
  state text not null default 'normal'
    check (state in ('normal','oily','loose','diarrhea','watery','fail')),
  memo text,
  created_at timestamptz not null default now(),
  deleted_at timestamptz           -- 소프트 삭제(휴지통)
);
alter table baechoo_stools enable row level security;
drop policy if exists "family_all" on baechoo_stools;
create policy "family_all" on baechoo_stools
  for all to anon, authenticated using (true) with check (true);
create index if not exists idx_baechoo_stools_date on baechoo_stools(date);
```

- 건강 기록 기존 18행은 `null`로 남는다(값 변경 없음). `baechoo_meals.time`과 같은 형식.
- `baechoo_stools`는 `uju_checklists`(0012)와 같은 골격. `state` 값은 `StoolState` 6종과 같다.

### 3.2 타입·저장소

- `BaechooHealth`에 `time: string | null` 추가. `repo`의 to/from 매퍼, localStorage 구버전 정규화(`time` 키 없으면 `null`).
- 새 엔티티 `BaechooStool {id, date, time, state, memo}` — 우주 체크리스트 표준 경로를 따른다: `types.ts`(인터페이스 + `DataSnapshot.baechooStools`) · `repo.ts`(to/from 매퍼, `loadAll` select `.is("deleted_at", null)`, 저장=`sbUpsert`·삭제=`sbSoftDelete`, **휴지통 4곳**=`loadBaechooTrash`·`restoreBaechoo`·`hardDeleteBaechoo`·`purgeOldBaechooTrash`에 테이블 추가) · `data-context.tsx`(state + refresh + 낙관적 mutator). localStorage 구버전 스냅샷엔 키가 없으므로 `[]`로 정규화.
- 🔴 **건강 탭 `HealthForm`은 화면은 그대로 두되 저장 시 `time: initial?.time ?? null`을 넘긴다.** 안 그러면 기타 기록을 건강 탭에서 한 번 고칠 때마다 시각이 지워진다(`Budget.sortOrder` 리셋과 같은 함정 — 행 전체 upsert). 건강 탭에서 새로 만든 기록은 시각 없이 저장되고 타임라인 「시각 없음」 줄에 나온다.

## 4. 이벤트 모델 — `lib/baechooEvents.ts` (순수함수, vitest)

네 테이블(식사·산책·응가·건강)을 하나의 이벤트 목록으로 합친다. **타임라인·마지막 기록·패턴 3종이 전부 이 목록 하나를 그린다** — 화면끼리 숫자가 갈라질 수 없게.

```ts
type EventKind = "meal" | "snack" | "walk" | "stool" | "etc";

interface BaechooEvent {
  key: string;              // `${kind}:${id}` — 리액트 키·중복 방지
  kind: EventKind;
  date: string;             // 로컬 YYYY-MM-DD (시작 기준)
  startAt: number | null;   // 로컬 시각의 epoch ms. null = 시각 없음(옛 건강 기록)
  endAt: number | null;     // 산책만, durationSec > 0일 때
  label: string;            // 식사·간식·산책 / 기타는 건강 종류 라벨(양치·약…)
  detail: string;           // 상세 한 줄
  stools: { at: number; state: StoolState }[]; // 산책만
  state?: StoolState;       // 응가만
  source: { table: "meal" | "walk" | "stool" | "health"; id: string };
}
```

- **시각 해석**: 식사·건강은 `new Date(\`${date}T${time}\`)`(로컬). 산책은 `startTime`(UTC ISO)을 `new Date()`로 읽어 로컬 날짜·시각을 다시 계산한다 — `walk.date`만 믿지 않는다.
- **응가 시각**: 산책 시작일 + `stool.time`. `stool.time < 시작 HH:MM`이면 다음 날로 본다(자정 넘긴 산책). `time`이 없으면 산책 시작 시각.
- 함수:
  - `toEvents(meals, walks, stools, health)` → `BaechooEvent[]`. 독립 응가는 `kind:"stool"` 한 시점 이벤트
  - `groupByDay(events)` → 날짜 desc, 그날 안은 시각 desc, `startAt === null`은 `untimed[]`로 분리
  - `daySummary(events)` → 식사 n · 간식 n · 산책 n회 m분 · 응가 n(독립 응가 + 산책 내 응가, 응가실패 제외)
  - `lastOf(events, kind)` / `lastStool(events)` — **독립 응가와 산책 내 응가 중 더 최근 것**. 🔴 `fail`(응가실패)은 응가로 치지 않는다
  - `elapsedLabel(fromMs, nowMs)` → `"2시간 13분 전"`
  - (패턴 계산은 `lib/baechooPattern.ts`) `patternItems(events, filter)` → 필터를 거친 시간순 목록(응가는 독립+산책 내 합침), `withIntervals(items)` → 이웃 간 간격(위 기록 시작 − 아래 기록 끝)
  - `dayLayout(items, date)` → 구간 `{kind, startMin, endMin}[]`(0~1440 clamp) + 응가 분 위치. 한 시점 기록과 끝 시각 없는 산책은 `POINT_MIN = 15`분 폭이고 그날에만 그린다. 자정을 넘긴 산책은 두 날에 나뉘어 나온다
  - `allStools(events)` → 독립 응가 + 산책 내 응가를 `{at, state, source}` 하나의 목록으로(패턴·간격·마지막 응가가 공유)
  - `weekDates(endDate)` → 7일, 날짜마다 `dayLayout`
  - `quickMeal(meals, mealType, now)` → 같은 `mealType`의 **직전 기록**(date·time 최댓값)에서 `content·topping·amount` 복사, `memo=null`, 시각=now. 직전이 없으면 빈 값

## 5. 기록 탭

위에서 아래로:

1. **헤더**: 「배추 생활기록부」 + 휴지통(그대로) + `Segmented [기록][패턴][건강][신체검사]`, 기본=기록
2. **원형 버튼 5개**(식사·간식·산책·응가·기타) — 종류색 원 + 흰 SVG 아이콘 + 라벨. 390px 폭에 한 줄로 들어가게(원 56px 안팎). 누르면 확인 없이 즉시 저장(§6)
3. **마지막 기록 3칸** — 마지막 식사(경과 + 사료명) / 마지막 산책(경과 + 소요) / 마지막 응가(경과 + 상태). 1분마다 갱신
4. **타임라인** — 날짜별 묶음, 최신 위
   - 머리줄: `10월 5일 (월)` + 오른쪽 `daySummary`
   - 행: `시각(오후 02:28) · 색 점 · 종류(종류색 글자) · 상세 한 줄 · ›`
     - 식사 `인섹트 프로틴 + 닭고기 · 1/1` / 간식 `육포 · 2`
     - 산책 시각 칸 `07:30` 아래 `~ 08:20`, 상세 `50분 · 응가 정상·묽음`
     - 응가 `정상` (메모 있으면 `정상 · 메모`)
     - 기타 `양치 · 칫솔질`
   - 그날 맨 아래 「시각 없음」 묶음(옛 건강 기록)
   - 처음 7일만, 맨 아래 「이전 7일 더 보기」

## 7. 상세 시트 (타임라인 행을 누르면)

- 시트 제목은 「기록 수정」, 본문 맨 위에 종류색 점 + 종류명 띠(Sheet 제목은 문자열이라). 공통: 날짜·시각(iOS 기본 휠).
- **식사·간식**: 사료(기존 `CategorySelect group=food multiple`), 토핑(식사만, `group=topping multiple`), 먹은 양(텍스트 + 최근 쓴 값 칩 최대 4개 — 같은 `mealType`의 최근 `amount` 고유값), 메모. 🔴 사료 필수 검사는 없앤다(빈 기록도 저장 가능해야 원탭과 맞다).
- **산책**: 시작 날짜·시각, 「+ 끝난 시각」(넣으면 `durationSec` 계산·표시, 지우면 0), 거리(km, 선택), 응가(기존 `StoolEditor`), 지도(기존 `WalkMap` — 지난 경로는 선, 새 기록은 점), 메모.
- **응가**: 날짜·시각, 상태 칩 6종(정상·기름기·묽음·설사·물·응가실패 — 기존 `STOOL_STATES`), 메모.
- **기타**: 종류 칩(양치·약·영양제·증상·병원·특이사항·기타 — `HEALTH_TYPES`에서 예방접종 제외. 옛 기록이 예방접종이면 그 칩도 보인다), 내용, 다음 예정일(선택), 메모.
- 하단: 「저장」 / 「기록 삭제」(기존 2단계 확인 → 소프트삭제).
- 시트는 조건부 마운트 + `key=이벤트 key`(useState 초기값 고착 방지 — 우주·계획 탭 패턴).

## 8. 패턴 탭

- `Segmented [일과표][주간 패턴][간격 패턴]`.
- **필터** 원형 토글 5개: 식사·간식·산책·응가·기타(기록 버튼과 같은 5종). 응가 필터는 독립 응가와 산책 내 응가를 함께 켜고 끈다. 세 화면 공용, 기기에 기억(localStorage `baechoo-pattern-filter`, try/catch, 기본 전부 켬).
- SVG 직접 렌더(Chart.js 안 씀). 앱의 밝은 테마 유지, 빈 시간은 `fill` 회색.

### 8.1 일과표 (하루 원형)
- 24시간 도넛, 0시 맨 위·시계방향, 2시간 눈금.
- 산책 = 실제 구간 호. 한 시점 기록·끝 시각 없는 산책 = 15분 조각. 응가 = 바깥 테두리 작은 표시.
- 가운데 날짜(오늘이면 「오늘」), 그날 요약은 원 아래 한 줄(가운데 원 폭에 안 들어감). 오늘이면 지금 시각 바늘.
- 순간 기록이 많아 원이 대부분 비어 보인다(하루의 ~4%만 칠해짐). 대안(아이콘 핀 + 지난 7일 겹침 / 평소 시간표)을 검토했으나 재헌 결정으로 현행 유지(2026-10-06).
- 하단 `‹ 2026년 10월 5일 (월) ›`, 기본=오늘.

### 8.2 주간 패턴 (7일 세로 막대)
- 하루=세로 막대, 위 0시·아래 24시, 양옆 3시간 눈금.
- 산책 블록, 한 시점 기록은 가로 띠(최소 높이 3px), 응가 아이콘.
- 지금 시각 가로선 + `11:55` 라벨. 날짜 라벨, 일요일 빨강.
- 기본 = 6일 전~오늘, `‹ 9월 30일 – 10월 6일 ›` 주 단위 이동.

### 8.3 간격 패턴
- 최신 위 세로 타임라인, 이웃 기록 사이에 간격 알약(`1시간 4분`). 필터와 결합(식사만 → 식사 간격).
- 응가 필터가 켜져 있으면 `allStools`(독립 응가 + 산책 내 응가)가 각각 행으로 나온다(배변 간격). 산책 내 응가 행을 누르면 그 산책의 상세 시트가 열린다.
- 날짜 경계에 「오늘」/「10월 5일」 구분선. 행을 누르면 §7 상세 시트. 처음 7일 + 더 보기.

### 8.4 대동여지도
