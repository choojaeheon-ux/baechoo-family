# 배추 식사 — 사료·토핑 다중 선택 (2026-08-18)

## 문제

배추 생활기록부 「식사」 탭에서 사료종류(`content`)와 토핑(`topping`)을 각각 **하나만** 고를 수 있다. 실제로는 건사료+습식을 섞어 주거나 토핑을 두세 가지 올린다. 지금은 그 기록을 남길 방법이 없다.

## 결정

### 저장 = 기존 텍스트 칸에 쉼표 조인

`baechoo_meals.content`(text not null)·`topping`(text)을 그대로 두고 여러 값을 `", "`로 이어 저장한다(`"건사료, 습식"`).

- 마이그레이션 없음 → **배포 순서 위험 0**. (0026 때 겪은 "컬럼 없는 DB에 새 코드가 붙으면 쓰기만 전멸" 창이 아예 안 열린다.)
- 과거 기록은 항목 1개짜리로 그대로 읽힌다. 승격 로직·localStorage 정규화 불필요.
- 대안이던 `text[]` 전환은 DDL을 재헌이 직접 적용해야 하고 순서 위험을 다시 여는데, 얻는 건 "항목 이름에 쉼표가 들어가도 안전" 하나뿐이라 접었다. 그 위험은 아래 입력 차단으로 막는다.

### 규약은 순수함수 두 개에만

`lib/mealNames.ts`

- `parseNames(s: string | null | undefined): string[]` — 쉼표 분리 → trim → 빈 값 제거 → 중복 제거(첫 등장 순서 유지)
- `joinNames(names: string[]): string` — 같은 정리 후 `", "` 조인, 비면 `""`

왕복(`join(parse(s))`)이 정규화된 문자열을 고정점으로 갖는다는 것을 vitest 불변식으로 잡는다. 레거시 단일값·빈값·앞뒤 공백·중복·구분자만 있는 문자열이 케이스.

### `CategorySelect`에 `multiple` 옵션

공용 컴포넌트(사료·토핑·신체검사 측정항목 3곳)의 외부 인터페이스 `value: string` / `onChange(v: string)`는 **유지**하고, `multiple`일 때만 내부에서 parse/join 한다.

- 호출부 변경은 `MealForm`의 두 줄에 `multiple` 추가가 전부
- **측정항목은 단일 유지** — parse를 안 타므로 이름에 쉼표가 있어도 안전
- 칩 재탭 = 해제. 선택 순서대로 뒤에 붙는다
- 저장 목록에 없는 값(구 기록)은 지금처럼 임시 칩. 다중에선 값별로 각각
- `+ 추가`로 만든 새 항목은 다중일 때 교체가 아니라 **추가 선택**
- `편집 ✕`로 옵션을 지우면 선택에서 그 이름만 빠진다(다중), 단일은 기존대로 비운다
- 다중 모드에서 새 항목 이름의 쉼표는 입력 시 제거 — 파싱이 깨지는 유일한 경로

### 적용 범위

식사의 사료종류·토핑, 그리고 같은 필드를 쓰는 간식종류. 저장 조건은 그대로 **최소 1개 필수**(`parseNames(content).length > 0`). 저장 시 `joinNames`로 정규화해 넣는다.

### 표시 — 변경 없음

`MealList`의 `MealCard`는 문자열을 그대로 렌더하므로 `건사료, 습식` / `토핑: 닭가슴살, 단호박`으로 자동 반영된다. 캘린더 날짜 패널도 같은 카드를 쓴다.

## 범위 밖

- 항목별 급여량 분리 입력(`amount`는 지금처럼 기록 전체에 하나)
- 신체검사 측정항목·건강 기록의 다중화
- 사료 조합 통계·분석
