# 예산 목록 순서 지정 + 계정과목 2단 선택 — 설계

- 작성 2026-08-02
- 선행: `2026-08-02-예산-버전-design.md`(예산 버전). 이 설계는 그 위에 얹힌다.

## 문제

두 가지다.

**① 대시보드 순서를 사람이 정할 수 없다.** 지금 `groupBurnRows`는 카테고리를 하위 예산 합 내림차순, 그 안 과목을 소진률 내림차순으로 자동 정렬한다. 금액이나 소진률이 바뀌면 순서가 흔들려서, 매달 같은 자리에서 같은 항목을 찾는 눈이 안 생긴다.

**② 계정 과목 선택이 33개짜리 단일 드롭다운이다.** 거래를 입력할 때마다 `주거비 · 월세`, `생활비 · 식비` 같은 항목 33개를 훑어 내려가야 한다. 재헌 표현으로 "매번 입력할 때마다 계정과목 찾는 것이 일".

## 해법 요약

- 예산 행에 `sort_order`를 두고, **과목 순서를 사람이 정한다.** 카테고리 순서는 소속 과목의 최소 순서로 **파생**한다 — 별도 저장소가 없다.
- 계정 과목 select를 **카테고리 → 과목 2단**으로 쪼갠다. 왼쪽 카테고리의 나열 순서도 위에서 정한 순서를 따른다.

## 1. 데이터 모델

```sql
budgets + sort_order integer
```

**버전별이다.** `sort_order`는 예산 행에 붙으므로 버전마다 독립이고, 버전을 복제하면 순서도 함께 복사된다(`duplicateBudgetVersion`이 행을 통째로 복사하므로 추가 작업 없음).

마이그레이션 **0026**. 기존 22행은 현재 화면에 보이는 순서 — 카테고리명 → 과목명 — 그대로 0부터 백필한다.

카테고리 순서를 담는 저장소는 **만들지 않는다.** 카테고리는 `Category.groupName` 문자열일 뿐이고, 순서를 따로 두면 과목을 옮길 때마다 두 곳을 맞춰야 한다.

## 2. 순서 해석

- **과목 순서** = 그 달 적용 버전 예산 행의 `sort_order` 오름차순
- **카테고리 순서** = 그 카테고리 소속 과목의 **최소 `sort_order`**
- **예산 행이 없는 과목** = 순서 없음. 순서가 지정된 것들 **뒤에**, 지금 방식(소진률 내림차순 / 그룹은 예산 합 내림차순)을 그대로 유지한다.
- `UNGROUPED`("미분류")는 지금처럼 항상 맨 뒤다.

예산 행이 없는 과목을 순서 대상에서 빼는 이유: 예산 탭 목록에 안 보이는 항목이라 순서를 매길 화면이 없다. 어머니 상환·기타·경조사·육아·교통·의료 등 10여 개가 여기 해당한다.

### 계산 함수에 미치는 영향

`BurnRow`에 `order: number | null`을 추가한다. `budgetBurndown`이 예산 행에서 읽어 실어 보내면, `groupBurnRows(rows)`는 **시그니처를 바꾸지 않고** 정렬할 수 있다.

```ts
export interface BurnRow {
  category: Category;
  budget: number;
  spend: number;
  pct: number;
  order: number | null; // 그 버전에서 사람이 정한 순서. 예산 행이 없으면 null
}
```

정렬 규칙:
- 행: `order`가 있는 것 먼저(`order` asc) → 없는 것은 뒤에 기존 `byBurn`
- 그룹: 멤버의 최소 `order`가 있는 그룹 먼저(그 값 asc) → 없는 그룹은 뒤에 기존 규칙(예산 합 desc) → `UNGROUPED` 맨 뒤

## 3. 예산 탭 — 카테고리 묶음 + 두 층 ▲▼

🔴 **평면 목록을 그대로 쓰지 않는다.** 평면에서 과목을 옮기면 `주거비·월세(1) / 생활비·식비(2) / 주거비·관리비(3)`처럼 카테고리가 흩어질 수 있는데, 대시보드는 카테고리로 묶으므로 관리비가 다시 주거비 밑으로 올라간다 — **두 화면이 달라 보인다.** 순서를 정하는 목적이 대시보드 반영이므로 이건 목적을 깬다.

그래서 예산 탭 목록을 **대시보드와 같은 카테고리 묶음 모양**으로 바꾸고 ▲▼를 두 층에 둔다.

```
일반 상태
┌─────────────────────────────────────┐
│ v1 · 과목별 예산     [순서 편집][+ 설정] │
│ ▸ 주거비                              │
│     월세      ₩0 / 540,000   수정 삭제 │
│     관리비    ₩0 / 150,000   수정 삭제 │
│ ▸ 생활비                              │
│     식비   ₩9,200 / 700,000  수정 삭제 │
└─────────────────────────────────────┘

「순서 편집」 켜면
┌─────────────────────────────────────┐
│ v1 · 과목별 예산            [편집 완료] │
│ ▸ 주거비                        ▲  ▼ │
│     월세            540,000     ▲  ▼ │
│     관리비          150,000     ▲  ▼ │
│ ▸ 생활비                        ▲  ▼ │
│     식비            700,000     ▲  ▼ │
└─────────────────────────────────────┘
```

- **과목 행의 ▲▼** = 같은 카테고리 안에서만 이동. 인접한 같은-카테고리 행과 `sort_order`를 교환한다.
- **카테고리 머리글의 ▲▼** = 그 카테고리를 통째로 이동. 소속 과목 전체가 함께 움직인다(인접 카테고리와 블록을 맞바꾼다).
- 맨 위의 ▲, 맨 아래의 ▼는 비활성.
- 카테고리 머리글은 기존 대시보드와 같은 `bg-stone` 띠 + 흰 글씨를 쓴다(이미 확정된 표기).

「순서 편집」이 꺼져 있으면 지금과 같이 `[수정][삭제]`만 보인다. 모바일 한 줄에 버튼 4개를 넣지 않기 위한 분리이고, 예산 소실 사고가 두 번 있었던 화면이라 삭제 버튼 옆에 새 버튼을 붙이지 않는다.

### 이동 저장

인접 두 행의 `sort_order`를 맞바꾸고 `saveBudget`을 두 번 호출한다. 카테고리 이동은 두 블록의 순서값 구간을 맞바꾸므로 그 안의 모든 행을 저장한다.

🔴 `saveBudget`은 실패 시 예외를 던진다(`sbUpsertOrThrow`). 이동 중 실패하면 순서가 반쯤 적용된 채로 남으므로, **낙관적 반영 전에 저장을 끝내고** 실패하면 사용자에게 알린다.

## 4. 계정과목 2단 선택

공용 컴포넌트 하나를 만들어 **거래 입력**과 **예산 설정** 두 곳에서 쓴다. 고정지출 등록과 거래내역 필터는 이번 범위 밖이다(입력 빈도가 낮고, 필터는 성격이 다르다).

```
┌─ 카테고리 ─────┬─ 계정 과목 ─────┐
│ 주거비       ▼ │ 월세         ▼ │
└───────────────┴────────────────┘
```

- 왼쪽 카테고리 나열 순서 = 그 달 적용 버전의 카테고리 순서(§2). 순서가 없는 카테고리는 뒤에 이름순, "미분류"는 맨 뒤.
- 왼쪽을 고르면 오른쪽은 그 카테고리에 속한 과목만 보여준다. 카테고리를 바꾸면 과목 선택은 초기화한다.
- 기존 값을 들고 열릴 때(수정)는 그 과목의 카테고리를 자동으로 골라 둔다.
- 거래 입력에서 지출↔수입 토글을 바꾸면 둘 다 초기화한다(현재도 `categoryId`를 비운다).
- 수입 과목은 `groupName`이 없어 "미분류"로 묶인다. 2개뿐이라 문제가 되지 않는다.

컴포넌트는 `components/budget/CategoryPicker.tsx`로 독립시킨다. `forms.tsx`가 이미 1,097줄이라 여기에 더 넣지 않는다.

## 5. 새 예산 행의 순서

`sort_order`는 그 버전의 최대값 + 1(맨 뒤). 같은 카테고리 옆에 자동으로 끼워 넣지 않는다 — 사용자가 「순서 편집」으로 옮기면 된다.

## 6. 테스트

`lib/compute.test.ts`:
- `budgetBurndown`이 예산 행의 `sort_order`를 `BurnRow.order`에 싣는가. 예산 행이 없는 과목은 `null`인가.
- `groupBurnRows`가 순서 지정 그룹을 먼저(최소 order asc), 미지정 그룹을 뒤에(기존 규칙), `UNGROUPED`를 맨 뒤에 두는가.
- 같은 그룹 안에서 order asc로 정렬되는가. order가 섞여 있으면(일부만 지정) 지정분이 앞인가.

🔴 픽스처에 실금액을 쓰지 않는다. 12345 / 23456 / 34567 계열을 쓰고 `reports/review-*.json`과 대조한다.

UI(▲▼ 이동, 2단 select)는 이 저장소 관례대로 유닛 테스트를 붙이지 않는다.

## 7. 범위 밖

- 고정지출 등록 폼과 거래내역 필터의 2단 전환
- 카테고리 자체를 엔티티로 승격(`event_categories`처럼) — 지금은 문자열 그룹명으로 충분하다
- 드래그 앤 드롭 — 이 앱은 캘린더 드래그에서 터치 함정(passive 이벤트·스크롤 충돌)을 이미 겪었고, ▲▼로 요구가 충족된다
- 예산 0원 과목을 예산 탭 목록에 노출
