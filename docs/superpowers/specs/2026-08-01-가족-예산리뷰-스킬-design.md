# 가족 예산 리뷰 스킬 (`family-budget-review`) — 설계

- 작성일: 2026-08-01
- 첫 적용: 2026-07 (7월분 리뷰)
- 관련: `skills/monthly-budget-review`(회사판, 신설·동대문 원장 기반) · `docs/가족-pnl/회계모델-규칙서.md`

## 배경

신설·동대문 지점의 월간 비용 집행 리뷰(`monthly-budget-review`)와 같은 방식으로
배추가족 앱의 월 예산 리뷰를 만든다. 배추가족 앱도 **계정 과목**을 축으로 설계되어 있어
리뷰 로직을 같은 모양으로 가져갈 수 있으나, 정본 데이터가 다르므로 별도 스킬로 만든다.

| | 회사판 | 가족판 |
|---|---|---|
| 정본 | FN 원장 xls + 비용관리 시트 | **배추가족 Supabase**(앱이 곧 정본) |
| 판단 축 | 매출 증분 대비 OPEX 증분(전년 동월) | **소진률 + 손익 2단** |
| 독자 | FO Weekly 구두 공유 | **재헌 점검 + 배찌 공유, 한 장에** |
| 산출물 | HTML | **PDF (A4)** |

가족은 수입이 회전에 따라 늘지 않으므로 회사판의 "매출 대비 검증" 축을 그대로 쓸 수 없다.
또한 거래가 2026-06부터라 전년 동월 비교가 불가능하다. 대신 **소진률로 "어디가 샜는가"를,
운영이익으로 "그래도 괜찮은가"를** 답하는 2단 구조로 간다.

## 핵심 결정

### D1. 계산은 앱 로직을 그대로 import한다 (재구현 금지)

`baechoo-family/lib/compute.ts`의 `budgetBurndown`·`groupBurnRows`,
`lib/pnl.ts`의 `computePnl`·`buildWaterfall`을 스킬 스크립트가 직접 import해 쓴다.

**근거**: 리포트와 앱 화면의 숫자가 어긋나면 배찌님과 보는 자리에서 논의가 거기서 멈춘다.
계산식을 파이썬 등으로 재구현하면 아래 규칙들이 두 벌이 되어 언젠가 조용히 어긋난다.
- 예산 0인데 지출이 있으면 소진률 `Infinity`(정렬은 뺄셈 금지, 비교로)
- 전체 소진률의 분자는 **예산을 안 잡은 과목의 지출까지 포함**
- 예산 조회는 "그 달 오버라이드 → 기본(`year_month = null`) → 없음" 순
- 손익 분류는 `category.cost_type`(fixed|variable|saving|excluded)을 그대로 따름

**실행 방식**: Node 24 네이티브 TS 타입 스트리핑 + resolve 훅.
앱 코드가 확장자 없는 상대 임포트(`./types`)를 쓰므로 Node ESM 해석이 실패한다.
`assets/hooks.mjs`가 `.ts`를 덧붙여 재시도한다(검증 완료).

```js
const HAS_EXT = /\.[cm]?[jt]sx?$/;
export async function resolve(spec, ctx, next) {
  if (spec.startsWith(".") && !HAS_EXT.test(spec)) {
    try { return await next(spec + ".ts", ctx); } catch {}
  }
  return next(spec, ctx);
}
```

**대가**: 스킬이 `baechoo-family` 레포 경로에 의존한다. 개인 볼트 전용이므로 수용.
앱 경로는 `--app` 인자로 받고 기본값 `C:\Users\MGRV\.claude\baechoo-family`.

### D2. 산출물·중간 파일은 GitHub 백업 밖에 둔다

볼트 `.gitignore`는 화이트리스트 방식이고 `/Output/`·`/skills/`가 **백업 대상**이다.
가족 금융 데이터는 원격 금지 방침(`/db-backups/`가 앱 레포에서 제외된 것과 같은 이유)이므로,
PDF·`review.json`·`context.json`은 전부 **`baechoo-family/reports/`** 에 둔다.
앱 `.gitignore`에 `/reports/`를 추가한다.

스킬 폴더(`skills/family-budget-review/`)에는 **코드와 예시만** 두고 실데이터·실맥락을 두지 않는다.
`context.example.json`의 값은 가상값으로 채운다.

### D3. 연납·격월 항목은 누적 기준으로 재평가한다

월 예산에 월 적립액으로 잡혀 있는데 실제로는 연 1회 청구되는 항목(자동차세 등)은
단월 소진률이 구조적으로 튄다. 격월 합산 청구(전기 등)는 반대로 0%가 뜬다.
이런 과목은 **단월 소진률 목록에서 빼고** 별도 섹션에서 누적 기준으로 본다.

- 연납: `연 예산(월 예산 × 12) 대비 연초~당월 누적 집행`
- 격월: 누적 집행과 다음 청구 예정만 표기, 소진률은 내지 않음(`—`)

`recurring_expenses` 테이블에는 주기 정보가 없으므로(월 고정만 표현) **`context.json`에서 지정**한다.
한 번 지정하면 매달 재사용된다.

### D4. 다음 달 예산 조정은 사실만 제시하고 수치를 제안하지 않는다

예산 미책정 과목의 실지출·월평균·상위 건까지만 보여주고, 권장 예산액은 내지 않는다.
배찌님과의 논의를 백지에서 시작하기 위한 것이며, 리포트가 결론을 선점하지 않는다.

## 리포트 구조

A4 세로. 섹션 번호는 표시되는 섹션에만 자동 부여(내용이 없으면 섹션째 숨김).

**요약 (헤더 KPI 4)** — 수입 · 지출 · 예산 대비 소진률 · 운영이익

1. **계정과목별 예산 소진률**
   앱 대시보드와 같은 배열: 카테고리 머리글(띠) + 하위 과목 들여쓰기, 한 줄에
   `[과목] [소진률] [(사용/예산)]` + 얇은 가로 막대. 소진률 높은 순, 그룹 순서는 하위 예산 합 순.
   색은 **소진 상태 하나만** 의미한다 — 기준 이하 초록 / 초과 빨강. 기본 기준 100%(`tol`로 조정).
   연납·격월 지정 과목은 여기서 제외.

2. **예산 미책정 과목**
   예산 0원인데 지출이 있는 과목. 과목별 당월 지출 + 최근 실적 월평균 + **금액 상위 건 드릴다운**
   (거래의 내용/거래처를 그대로 노출). 거래 단위 데이터가 있어 회사판에는 없는 섹션이다.
   합계를 명시해 당월 초과분과의 관계를 보여준다.

3. **연납·격월 (누적 기준)** — D3 참조. `context.annual`이 비면 섹션 숨김.

4. **미집행** — 소진률 50% 미만이고 미집행액이 5만원 이상인 과목(둘 다 `context`로 조정 가능).
   `cost_type=saving` 과목의 미집행은 맨 위에 따로 둔다 — 선저축 미실행은 절약이 아니라
   계획 미이행이므로 성격이 다르다.

5. **손익** — 폭포(매출 − 고정비 − 선저축 − 변동비 = 운영이익) + 운영이익률 + BEP 달성 여부.
   "예산은 초과했으나 잉여는 확보"인지 여기서 판정한다.

6. **논의 안건** — `context.agenda`의 항목만. 사실 + 빈칸, 권장치 없음(D4).

## 파일 구조

```
skills/family-budget-review/
  SKILL.md
  assets/hooks.mjs             Node TS resolve 훅 (D1)
  assets/extract.mjs           Supabase REST → 앱 로직 계산 → review.json
  assets/build.mjs             review.json + context.json → HTML → PDF
  assets/template.html         A4 인쇄 레이아웃
  assets/context.example.json  가상값 예시 (실맥락 금지, D2)
```

### `extract.mjs`
- `.env.local`에서 `NEXT_PUBLIC_SUPABASE_URL`/`ANON_KEY`를 읽어 REST로 조회
- 테이블: `categories` · `budgets` · `transactions` · `recurring_expenses`
- **이 4개 테이블에는 `deleted_at`이 없다**(하드 삭제). 배추·우주 테이블과 달리 소프트 삭제 필터를
  걸면 PostgREST가 `42703`으로 400을 낸다 — 걸지 않는다
- PostgREST 기본 응답 상한이 있으므로 `limit`을 명시하고, 반환 건수가 상한과 같으면 페이지네이션한다
  (조용한 절단 금지)
- 앱 로직으로 `budgetBurndown`·`groupBurnRows`·`computePnl`·`buildWaterfall` 실행
- 미책정 과목의 상위 건, 최근 N개월 평균을 함께 산출.
  건별 표기는 `merchant`(비어 있는 경우가 많음)와 `memo`를 함께 쓴다
- 결과를 `review.json`으로 저장하고, 콘솔에 초과·미책정·미집행 목록을 출력한다
  (이 목록이 `context.json`을 채우는 재료다)

### `build.mjs`
- `review.json` + `context.json` → `template.html`의 `__DATA__` 치환 → HTML
- Chrome을 `--headless --print-to-pdf`로 호출해 PDF 생성
- Chrome 경로 탐색 순서: `--chrome` 인자 → `%ProgramFiles%` → `%ProgramFiles(x86)%` → `%LOCALAPPDATA%`.
  못 찾으면 실패로 알린다(조용한 HTML-only 폴백 금지)
- `context`에 없는 초과 과목이 있으면 경고를 남긴다(미분류 방치 금지)

### `template.html`
- **차트는 CSS/인라인 SVG로 그린다. Chart.js를 쓰지 않는다.**
  인쇄 시 canvas 렌더 타이밍 문제가 없고, 폭포·가로 막대는 div/SVG로 충분하다.
- `print-color-adjust: exact`(+`-webkit-` 접두)를 지정해야 헤드리스 인쇄에서 막대 색이 살아난다
- `@page { size: A4; margin: … }`, 섹션 경계에 `break-inside: avoid`
- 브랜드 폰트는 쓰지 않는다(개인 프로젝트, 앱 톤을 따른다)

### `context.json` (사람 판단)
```jsonc
{
  "ym": "2026-07",
  "tol": 100,                    // 소진률 허용 기준 %
  "avgMonths": 2,                // 미책정 과목 평균 산출 기간
  "annual": [                    // D3. 한 번 지정하면 매달 재사용
    { "category": "자동차세", "kind": "annual" },
    { "category": "전기",     "kind": "bimonthly", "note": "격월 합산 청구" }
  ],
  "notes": { "의료/건강": "출산 관련 진료·한약" },   // 과목별 사유 한 줄
  "agenda": ["예산 미책정 과목 중 상시 지출 항목 확정"],
  "underspend": { "minGap": 50000, "maxPct": 50 }
}
```

`annual`·`notes`의 키는 **계정 과목 이름**으로 매칭한다(id가 아님 — 사람이 쓰는 파일이므로).
이름이 DB에 없으면 오타이므로 경고를 내고 그 항목을 무시한다. 조용히 넘기지 않는다.

## 톤

사용자 전역 규칙을 따른다.
- 한국어, 명사형 종결(명사형만 마침표 생략, 동사형은 유지)
- 이모지 없음
- 리드 1문장 · 인사이트 2문장(결론 + 근거) 하드 리밋. 정의·산식 설명을 리포트에 넣지 않는다
- "고객" 금지(해당 없음이나 규칙 유지)

## 검증

- **1차**: 리포트의 소진률·지출 합계가 앱 화면(가계부 대시보드 / 손익 대시보드)과 일치하는지 대조.
  D1의 목적이 이것이므로 불일치는 곧 결함이다.
- **2차**: 예산 미책정 과목 합계 + 예산 과목 초과분 = 전체 초과분인지 산술 확인
- **3차**: PDF를 열어 A4 경계에서 섹션이 잘리지 않는지, 막대 색이 나오는지 확인

## 범위 밖

- 앱 코드 변경 없음(읽기 전용). 예산 입력·수정은 앱에서 한다
- 연납·격월 주기를 DB 스키마에 넣는 것 — `context.json`으로 충분하고, 스키마 변경은 별건
- 회사판 `monthly-budget-review`는 건드리지 않는다
