# 데일리 투두 순서 편집 — 설계

- 날짜: 2026-08-19
- 대상: 배추가족 PWA (`baechoo-family`)
- 선행: `2026-08-18-데일리-투두-탭-design.md`

## 1. 목표

데일리 투두의 카테고리 순서와, 카테고리 안 항목 순서를 화면에서 직접 바꾼다.

## 2. 화면

체크리스트 위에 `순서 편집` ↔ `편집 완료` 토글. 예산 탭(`components/budget/BudgetVersions.tsx`)과 같은 문구·같은 자리다.

편집 모드일 때:
- 카테고리 헤더 우측에 ▲▼
- 각 항목 우측의 `편집` 버튼이 ▲▼로 교체된다 — 모바일에서 한 줄에 버튼이 4개가 되는 것을 막는다(예산 탭이 같은 이유로 택한 방식)
- 체크 토글은 잠긴다. 순서를 옮기다 실수로 체크되는 것을 막는다
- 맨 위의 ▲, 맨 아래의 ▼는 비활성
- 저장 중에는 전부 비활성 (연타 방지)

드래그는 쓰지 않는다. 캘린더 그리드 드래그에서 터치 함정을 겪은 뒤 예산 탭이 ▲▼로 간 선례를 따른다.

## 3. 계산 — `lib/dailyTodoOrder.ts`

순수함수 2개. 둘 다 변경된 것을 포함한 전체 배열을 돌려주고, 원본을 변형하지 않는다.

```ts
moveCategory(cats: DailyTodoCategory[], catId: string, dir: -1 | 1): DailyTodoCategory[]
moveTodo(todos: DailyTodo[], visibleIds: string[], todoId: string, dir: -1 | 1): DailyTodo[]
```

### 3.1 `visibleIds`가 이 설계의 핵심

메인 화면은 그날 활성인 항목만 보여준다. 예산 탭의 `reindex`처럼 전체를 0..n-1로 다시 매기면, **오늘 화면에 없는 1회성 항목들의 순서가 조용히 재배치된다.** 거기서는 목록 전체가 화면에 있어 안전했던 방식이 여기서는 안전하지 않다.

그래서 이동은 이렇게 정의한다.

> "위로" = 같은 카테고리 안에서, **화면에 보이는 바로 위 이웃**과 `sortOrder`를 맞바꾼다.

화면에 없는 항목의 `sortOrder`는 건드리지 않는다. 결과적으로 안 보이는 항목이 두 항목 사이에 남을 수 있지만, 그날 화면에서는 보이지 않으므로 사용자의 의도("C를 A 위로")와 어긋나지 않는다.

### 3.2 값이 겹칠 때

`sortOrder`가 같은 항목이 둘 있으면 맞바꿔도 순서가 그대로라 버튼이 죽은 것처럼 보인다. 시드나 백필로 생길 수 있다.

그래서 맞바꾸기 전에 충돌을 검사하고, 있으면 **현재 표시 순서를 유지한 채** 전체를 0..n-1로 다시 매긴 뒤 맞바꾼다. 이동 한 번이 자가 치유가 된다 — `lib/budgetOrder.ts`의 `reindex` 주석과 같은 논리다.

정규화는 현재 순서를 보존하므로, 이 경우에도 안 보이는 항목의 **상대 순서**는 바뀌지 않는다.

### 3.3 카테고리

`moveCategory`는 전체 카테고리 배열을 대상으로 한다. 메인 화면에는 그날 항목이 있는 카테고리만 뜨지만, 순서는 전역 속성이므로 보이지 않는 카테고리도 함께 정렬된다. 항목과 달리 카테고리는 수가 적고 전부 `dailyTodoCategories`에 있으므로, 여기서는 전체 재부여가 안전하다.

## 4. 저장

예산 탭 `applyOrder`(`BudgetVersions.tsx:74`)를 복제한다.

- 현재 `sortOrder`와 diff해서 **바뀐 행만** 저장
- 바뀐 것이 없으면 아무것도 하지 않는다
- `saving` 상태로 중복 실행을 막는다
- 실패 시 `console.error` + `window.alert("순서를 저장하지 못했어요. 다시 시도해 주세요.")`

저장소 이중화는 기존 `saveDailyTodo` / `saveDailyTodoCategory`를 그대로 쓰므로 추가 배선이 없다. 마이그레이션도 없다 — `sort_order` 컬럼은 0027에 이미 있다.

## 5. 테스트 — `lib/dailyTodoOrder.test.ts`

1. 카테고리를 한 칸 올리면 그 둘의 순서만 바뀐다
2. 항목은 같은 카테고리 안에서만 움직인다 (경계를 넘지 않는다)
3. 첫 항목의 ▲, 마지막 항목의 ▼는 무동작
4. **화면에 보이지 않는 항목의 `sortOrder`는 변하지 않는다**
5. `sortOrder`가 겹쳐 있어도 한 번 이동하면 순서가 정상화되고 의도대로 움직인다
6. 이동은 원본 배열과 원본 객체를 변형하지 않는다
7. 없는 id·범위 밖 요청은 입력과 같은 순서를 돌려준다

## 6. 범위 밖

- 드래그 앤 드롭
- 카테고리 간 항목 이동 — 편집 시트의 카테고리 드롭다운이 이미 한다
- 관리 시트의 별도 순서 UI — 같은 `sortOrder`를 읽으므로 자동으로 따라간다
